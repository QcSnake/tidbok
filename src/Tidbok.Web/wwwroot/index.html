Så funkar det

Det som brukar gå fel med bokningar, löst från början

01Ingen dubbelbokning

Två kunder som klickar på samma tid samtidigt får inte båda den. Bokningen kontrolleras en gång till inne i ett databaslås innan den sparas, och ett test skickar tjugo samtidiga bokningar för att bevisa det.

02Röda dagar sköter sig själva

Påsk, Kristi himmelsfärd, midsommar och alla helgons dag räknas fram för varje år. Ingen behöver komma ihåg att stänga juldagen i januari.

03Kunden avbokar själv

Bekräftelsen har en egen länk och en kalenderfil. Kunden kan avboka fram till en gräns ni väljer, efter det hänvisas de till telefonen.

04Uppgifterna gallras

Namn, telefon och meddelande tas bort 30 dagar efter besöket. Bokningen finns kvar i statistiken, personen gör det inte.

Tekniken

Byggt i C# och .NET 8

Koden ligger öppen på GitHub. Hur och varför står i fallstudien.

Backend
ASP.NET Core minimal API för bokningen, Razor Pages för adminvyn.
Data
SQLite med skrivlås per bokning. Tunt eget lager mot C-API:t, all SQL parametriserad.
Frontend
Vanlig JavaScript utan ramverk. Widgeten är en fil på några kilobyte.
Tester
xUnit för reglerna, flödet mot en riktig databasfil och samtidiga bokningar.
Säkerhet
Strikt CSP, PBKDF2-lösenord, begränsning av antal anrop, avbokningslänkar som bara sparas som hash.
Drift
Docker på Render. Testerna körs i bygget och stoppar en trasig version.
